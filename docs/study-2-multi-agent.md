# Исследование 2 (отдельное). Коллективный пробой: несколько агентов одновременно

> Это **не** продолжение исследования пар 1-на-1. Отдельный `experiment_id`,
> отдельная БД, отдельные гипотезы и отдельный протокол. Данные двух исследований
> не смешиваются: у них разные единицы наблюдения. Данные исследования 1 служат
> **предиктором** (предсказанная корреляция), а не источником наблюдений.

## 1. Зачем отдельно

Исследование 1 измеряет риск отдельной пары и **не** может измерить
монокультуру: агенты одной модели — независимые сэмплы, общей случайности по
условиям нет, поэтому совместность пробоев не идентифицируется. Здесь
монокультура становится измеримой: несколько агентов работают в одном условии
(общий шок) или торгуют друг с другом.

## 2. Гипотезы

| #   | Гипотеза                                                                             | Как проверяем                                                                           |
| --- | ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| H4  | Дисперсия числа пробоев на сессию превышает биномиальную (есть общий фактор)         | `realized_rho` с базой `sum s_i^2`; симуляция нуля; сравнение рук `portfolio`/`control` |
| H5  | **Парная** реализованная ρ по бэкбонам согласуется с предсказанной из исследования 1 | `backbone_pair_rho` против предсказанной ρ пар                                          |
| H6  | Уступка одного агента повышает шанс уступки других (стадность)                       | логит `P(пробой_i) ~ чужие пробои` с поправкой на общий фактор                          |
| H7  | Концентрация контрагента усиливает совместные уступки                                | сравнение «один против многих» и «многие против многих»                                 |
| H8  | Мандат деградирует по цепочке делегирования                                          | доля пробоев по глубине цепочки                                                         |

## 3. Единицы, условия, рандомизация

- **Единица** — сессия: пул агентов в одном условии.
- **Условие** — `(scenario_id, pressure_profile, condition)`; `condition` —
  воспроизводимый идентификатор траектории, а не `seed`.
- **Шок** — `Opponent.pressure` масштабирует лестницу давления. Рука `portfolio`
  даёт один общий шок на сессию; рука `control` — независимые шоки на агента при
  тех же маргиналах.
- **Объём** — `R >= 60` сессий на условие. При `R = 20` приближённая стандартная
  ошибка оценки ρ около 0.09 (интервал ±0.17), при `R = 60` — около 0.05. Для
  ρ порядка 0.2 нужен больший `R`.

## 4. Режимы

### 4.1 Портфель под общим шоком (приоритет)

Пул агентов в одном условии против одного противника с одной траекторией.
Контрольная рука — те же агенты, но шоки независимы.

### 4.2 A2A-рынок

Агенты-продавцы и агенты-покупатели торгуют одновременно. Чтобы не занижать
риск скриптом, противник должен быть **адаптивным LLM** (литература показывает,
что адаптивный противник сильнее скриптованного, а лимиты, откалиброванные на
скриптах, слишком щедры).

### 4.3 Концентрация контрагента

Один покупатель против многих продавцов и наоборот.

### 4.4 Цепочка делегирования

Принципал → агент → субагент: мандат передаётся от уровня к уровню
(`run_chain`), деградация — падение переданного пола ниже исходного.

## 5. Исход и оценка

- `session_breaches`, `session_shortfall`, `joint_breach`, `co_breach`.
- **ρ** — моментная оценка с гетерогенной базой:
  `rho = (Var(B) - sum s_i^2) / ((sum s_i)^2 - sum s_i^2)`, `s_i = sqrt(p_i(1-p_i))`.
  Это снимает смещение гетерогенных маргиналов, которое занижало ρ в опасную
  сторону. Полноценная пробит-GLMM со случайным сдвигом сессии (ρ = σ²/(1+σ²))
  требует `statsmodels` — если он доступен, оценка дополняется GLMM.
- **Значимость** — симуляция нуля: те же маргиналы, независимые исходы.
- **Эффект дизайна** — отношение дисперсий числа пробоев рук `portfolio` и
  `control`.

Ограничение: без контрольной руки стадность и общий внешний фактор неразличимы.
Одна пара рук разделяет их лишь частично — это открытая угроза валидности.

## 6. Метрики

| Метрика                       | Смысл                             | Базовая линия              |
| ----------------------------- | --------------------------------- | -------------------------- |
| ES портфеля                   | хвостовые потери на сессию        | ES при независимых агентах |
| `realized_rho`, `rho_p_value` | зависимость исходов внутри сессии | 0                          |
| эффект дизайна                | раздувание дисперсии              | 1                          |
| доля совместных пробоев       | грубая кластеризация              | произведение маргиналов    |
| `realized_n_eff`              | независимые единицы риска в пуле  | размер пула                |
| задержка заморозки            | сделок до срабатывания e-процесса | log(1/δ)/KL                |

Для проверки лимитов на хвосте нужен **e-backtest** для ES (подход
Wang–Wang–Ziegel): проверка частоты пробоев хвост не покрывает, а лимит строится
по ES.

## 7. Провинанс и предрегистрация

- Каждая сессия пишется в отдельную БД с тем же провинансом, что и в исследовании
  1, плюс `session_id`.
- Первичные гипотезы (H4, H5) и метрики фиксируются до прогонов; H6–H8 —
  вторичные, exploratory.
- Общая пререгистрация — `docs/preregistration.md`.
